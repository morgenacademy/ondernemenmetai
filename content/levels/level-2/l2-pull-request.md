Je interviews en je analyse zijn nieuw: die komen direct in je repo. Je canvas en je aannames zijn van jou. Daar stelt je AI wijzigingen voor, en jij beslist. Dat doe je met een pull request. Zo zie je ook wat de markt je leerde.

### Zo gaat een pull request

1. Je AI zet de wijziging op een zijspoor, een branch. De hoofdversie van je repo blijft zoals hij was.
2. Klik in GitHub Desktop op **Publish branch**. Het zijspoor staat nu ook op GitHub.
3. Klik op **Create Pull Request**. GitHub opent in je browser. Klik daar op **Create pull request**.
4. Open **Files changed**: in rood zie je wat sneuvelde, in groen wat erbij kwam.
5. Klopt het? Klik op **Merge pull request** en daarna op **Confirm merge**. Het zijspoor is nu samengevoegd met je repo, en het platform telt het mee.

Klopt het niet? Vraag je AI om het aan te passen. De pull request werkt zich vanzelf bij.

### Ook een pull voegt samen

Merge betekent samenvoegen. Bij een pull gebeurt hetzelfde: wat op GitHub nieuw is, komt bij wat op je computer staat. Meestal doet git dat zelf. Lukt het niet, dan legt je AI uit wat er speelt.

### Wat alleen op je computer staat

Je opnames staan in `interviews/`, naast de uitgeschreven gesprekken. `.gitignore` zorgt dat git ze overslaat, dus ze komen nooit op GitHub. Zo blijven stemmen en namen op je eigen computer.

### Wanneer een pull request?

Alleen als je AI iets aanpast wat jij koos: je idee, visie, madlib, canvas, aannames of doelgroep. Interviews, analyses en ander materiaal komen direct in je repo.
